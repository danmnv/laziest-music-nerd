# Бэкап и восстановление

## Что где лежит

| Что | Где | Защищено? |
|---|---|---|
| Код, обзоры, оценки критиков, сайт (`data/*.json`) | git на GitHub | Да: вся история в git, плюс копия на любом компьютере, где делали `git clone` |
| Данные людей: подписки на артистов, «Слушал» / «Отложить» / «Не моё», свои оценки, голоса за настроение | Cloudflare D1 (база `laziest-music-nerd`) | Да, двумя способами ниже |
| Секреты (токены, ключи) | GitHub Secrets, Cloudflare | Не бэкапятся: их нельзя прочитать обратно. Новый токен всегда можно выпустить заново |

## Способ 1. Time Travel (откат на 7 дней)

Cloudflare сам, бесплатно и без настройки, помнит каждое изменение базы D1 за последние **7 дней** (на платном плане 30).
Это подходит для «что-то сломалось вчера»: можно откатить базу на любую минуту в этих 7 днях.

Как откатить:
1. GitHub → вкладка **Actions** → слева **«Откатить базу D1 (Time Travel)»** → **Run workflow**.
2. В поле «Куда откатить» впиши время **по UTC** (Москва минус 3 часа), например `2026-11-02T08:00:00Z`.
3. В поле подтверждения впиши `ОТКАТИТЬ` → зелёная кнопка **Run workflow**.
4. В итогах запуска будет закладка «вернуть как было». Если откатил не туда, запусти ещё раз и вставь эту закладку в «Куда откатить».

Откат заменяет базу целиком: всё, что люди отметили после выбранного момента, пропадёт (пока не вернёшь закладкой).
Запуск с пустыми полями ничего не меняет, только показывает текущую закладку.

Чего Time Travel не спасает: ошибку, замеченную позже чем через 7 дней, и удаление самой базы (история хранится внутри неё).

## Способ 2. Ежедневный бэкап (90 дней)

Workflow **«Бэкап базы D1»** каждый день в 4:23 по Москве выгружает базу, проверяет, что выгрузка читается
и в ней столько же строк, сколько в базе, шифрует и сохраняет как файл запуска (artifact) на 90 дней.

Почему зашифровано: репозиторий публичный, и файлы запусков может скачать любой, кто вошёл в GitHub.

### Ключ шифрования: секрет BACKUP_KEY (один раз, 2 минуты)

1. Придумай длинный случайный пароль: **40+ символов**, например сгенерируй в менеджере паролей.
   Не используй токен бота или другой ключ проекта и **никуда его не вставляй, кроме GitHub** (ни в чат, ни в код).
2. Сохрани копию в менеджере паролей или заметках, доступных только тебе.
   Для восстановления она не нужна (оно идёт в GitHub, где секрет уже лежит), но если секрет перезаписать, старые бэкапы открываются только этой копией.
3. GitHub → репозиторий → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**.
   Name: `BACKUP_KEY`, Secret: твой пароль → **Add secret**.

Пока секрета нет, бэкап всё равно делается, но шифруется ключом из токена бота (в запуске будет жёлтое предупреждение,
а имя файла кончается на `.tok.gpg`). У такого бэкапа два минуса: его откроет любой, у кого есть токен бота,
и после смены токена он откроется только старым токеном. С `BACKUP_KEY` (файлы `.key.gpg`) оба минуса уходят.

### Копия в Telegram (раз в неделю)

Когда добавлен `BACKUP_KEY`, по воскресеньям (и при каждом ручном запуске бэкапа) бот без звука присылает тебе в личку
зашифрованный файл бэкапа. Эта копия живёт вне GitHub и Cloudflare и не исчезает через 90 дней. Перешли её в «Избранное», если хочешь.
В подписи к файлу есть код. Чтобы восстановить базу из этого файла, вставь код в поле «Telegram» в workflow восстановления.
Без `BACKUP_KEY` бот ничего не шлёт: файл с ключом из токена бота смог бы открыть любой, у кого есть этот токен.
Если пропадёт и GitHub, файл откроется только твоей копией `BACKUP_KEY`, поэтому её стоит хранить у себя.

### Проверить, что бэкап восстанавливается (база бота не трогается)

1. **Actions** → **«Восстановить базу D1 из бэкапа»** → **Run workflow**.
2. Режим `test`, остальные поля пустые → **Run workflow**.
3. Он создаст временную отдельную базу, зальёт туда последний бэкап, сверит число строк и удалит её.
   Зелёная галочка и «✅ Восстановление сходится» в итогах = бэкап рабочий.

### Восстановить по-настоящему

Только если Time Travel уже не помогает (больше 7 дней или база удалена).
1. Тот же workflow, режим `live`.
2. «Номер запуска»: пусто = последний удачный бэкап. Нужен более старый: открой нужный запуск «Бэкап базы D1»,
   число в конце адреса страницы (`.../actions/runs/12345678901`) и есть номер.
3. В поле подтверждения впиши `ЗАМЕНИТЬ`.

Он сначала запишет закладку Time Travel текущей базы (её видно в итогах: этим можно отменить замену в течение 7 дней),
потом заменит все таблицы данными из бэкапа и добавит таблицы, которые появились позже бэкапа (пустыми).

Если базу удалили совсем: сначала запусти **«Деплой Cloudflare Worker»** (он создаст пустую базу и подключит к ней бота),
потом восстановление в режиме `live`.
